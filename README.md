# 见程 · AI 求职行动伙伴

一个面向中国大陆早期职业阶段求职者的网页。把真实岗位、自己的经历、简历版本、申请事件与反馈连成下一步。无需登录或密钥即可完成基础求职流程；AI 接口完全可选。

现有网址：[jiangjinzhou01-ctrl.github.io/xiayibu](https://jiangjinzhou01-ctrl.github.io/xiayibu/)。

## 现在可以做什么

- **今天：** 一个最值得做的行动、待跟进日期、已保存的机会和基于本地记录的观察。
- **机会：** 粘贴岗位原文或链接，按证据分析可取之处、尚未提供的证据、待核实条件与风险线索；自主选择投递时机，记录投递、笔试、面试和结果。正式申请仍在招聘原站完成。
- **伙伴：** 带当前岗位和可选择的档案上下文提问；本地规则模式免费，兼容 API 或独立联网接口需要用户配置。左上角的对话列表支持新建、搜索历史内容和继续旧对话；全局记忆可以在列表中编辑，并按条控制在线发送。
- **我的：** 求职目标、真实经历证据、简历版本、文本面试练习、每周复盘、数据备份与模型设置。

本地规则模式不具备大模型生成能力，不抓取实时职位，也不能判断录用概率或招聘信息真假。岗位来源和时效请在招聘原站核实。浏览器小模型需用户主动下载，当前仅适合英语实验，中文回退到本地规则。

## 隐私与数据迁移

业务资料默认保存在此设备的 IndexedDB；不能使用 IndexedDB 时回退到本地存储。清除浏览器数据或换设备前，在「我的 → 数据与备份」导出 JSON。可导入见程或旧版职向备份。

首次打开会从旧版 `xiayibu-v1` 及伙伴本地记录迁移岗位、任务、简历、聊天、手动记忆与不含密钥的供应商设置。旧版浏览器存储不会自动删除；迁移前原始快照可单独下载。无法无损解释的旧投递状态保留原文并要求人工确认。新填的 API 密钥和 Worker 访问令牌按网关地址分别保存在当前浏览器的本地存储，刷新后仍可使用；可在「我的 → 模型与联网」移除。它们不进入备份、源码或仓库，但同一设备的其他浏览器用户或页面脚本可能读取本地存储，共用设备请移除。在线提问时，本次对话会发给用户设置的供应商；职业档案和长期记忆需要分别勾选授权。

## 开发和发布

需要 Node.js 24。源码在 `web/src/`，使用 Vite、TypeScript 和 Preact；独立联网示例在 `worker/`。根目录的 `index.html`、`assets/`、`icon.svg`、`model.worker.js` 是构建结果，当前 GitHub Pages 从 `main` 分支根目录发布。

```bash
npm ci
npm run dev
npm run check
npm run publish:root
```

开发时 Vite 使用 `/xiayibu/` 子路径。修改源码后运行 `npm run publish:root`，提交源文件及根目录的构建结果；GitHub Pages 将随 `main` 更新。`.github/workflows/verify.yml` 会检查类型、构建以及发布文件是否与源码一致。

## 自带 API 与联网

在「我的 → 模型与联网」输入供应商网关原地址、密钥并检测模型；无需手动补 `/v1` 或 `/v2`。支持 OpenAI 兼容 Chat Completions 与 Claude 原生 Messages API。供应商须允许浏览器跨域；无法提供标准模型列表时可输入模型名与同域名的 API 基址。模型支持的输出长度、思考深度和费用以供应商为准，自动输出不意味着无限 Token。界面只显示服务实际返回的思考内容。

联网搜索是可选的独立 Worker：将 `worker/index.js` 部署到自己的 Cloudflare 账户，把 `OPENAI_API_KEY` 与 `AGENT_ACCESS_TOKEN` 设置为 Worker Secret，并设置 `APP_ORIGIN`、费用与访问限制，再在见程内填写 Worker 地址和访问令牌。GitHub Pages 不能保存服务端密钥；普通兼容聊天也不自动拥有联网搜索。只有用户开启联网搜索后，Worker 才请求网页搜索，引用仍需自行核对。不要把任何密钥提交进公开仓库。
